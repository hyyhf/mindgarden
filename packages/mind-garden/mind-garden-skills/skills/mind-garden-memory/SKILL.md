# 心智庭院记忆提炼

任务不是复述聊天，而是判断这次对话里有没有值得在近期继续理解用户的重要信息。

只保留用户亲自表达、并且以后可能影响理解或支持方式的内容，例如正在持续的处境、核心困扰、明确约束或决定、重要关系、用户明确说出的价值判断、希望 Agent 如何回应，以及与当前问题确实有关的身份和现实背景。

先检查当前处境、核心困扰、决定与约束、支持偏好、关系、价值判断和身份背景。不要因为某条信息出现得早、措辞更短或更容易概括，就让它挤掉会直接影响下一次支持方式的中心信息。优先级通常是明确的支持偏好、仍在持续的核心处境、现实决定或约束、反复困扰，高于孤立且与当前问题无关的身份事实。

不要保存寒暄、测试 Agent 的问题、临时操作指令、单纯知识提问、没有上下文的情绪词、Agent 自己的推断，以及任何粘贴进来的旧笔记。密码、令牌、证件号码、银行卡号和精确住址不得成为记忆。不要把一次情绪推断成人格，不要把问题改写成用户已经认同的结论。

找出零至八条候选；没有足够重要的信息时必须输出空数组，不要因为对话很长而凑数。每条使用第一人称、一至两句、可独立理解的自然语言，最多 160 个汉字。相同事实只保留一次。

每条候选必须引用一条用户原话。只有输入明确提供消息 ID 时才能使用；否则 `sourceMessageId` 为空字符串。`evidenceQuote` 必须逐字出现，最多 120 个汉字。结果只是待确认候选，不得声称已经写入长期记忆。

只输出 JSON，不使用 Markdown 代码围栏：

```json
{
  "memories": [
    {
      "content": "我喜欢打篮球。",
      "kind": "preference",
      "sourceMessageId": "输入提供的用户消息 ID，或空字符串",
      "evidenceQuote": "我的爱好是篮球",
      "confidence": 0.92,
      "importance": 0.78,
      "reason": "这是明确而稳定的爱好，可能影响以后理解我的兴趣与生活。"
    }
  ]
}
```

`kind` 只能是 `fact`、`preference`、`value`、`support-preference`、`decision`、`emotion` 或 `episode`。`confidence` 低于 0.65 的内容不要输出。`importance` 表示未来 30 天内对理解用户或选择支持方式的价值，不要用情绪强度代替重要性。
