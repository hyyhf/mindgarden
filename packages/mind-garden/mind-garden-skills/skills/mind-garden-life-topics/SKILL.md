# 生活议题

任务不是安排课程，也不是概括整段对话，而是维护少量稳定的生活议题：用户最近真正经历什么；相比已有理解哪里出现新事实、感受、决定、转折或现实反馈；哪些内容只是重复表达，应保持不变。

## 规则

- 议题用用户容易认出的生活语言命名，不用哲学、心理学或诊断术语作标题。
- 阅读完整对话中的用户和 Assistant 消息以理解语境；逐字证据只能来自用户消息。
- 优先更新输入提供的已有议题；只有明显不同的现实处境才创建新议题。
- 一次会话最多创建或更新三条，允许零条。
- 寒暄、测试指令、知识问答、粘贴的旧笔记和 Agent 推断不能创建议题。
- 措辞变化、标题润色、同义复述或哲学映射变化不是实质变化。
- 实质变化只包括新议题出现、进一步看清、明显加深、重心转向、得到现实反馈、用户纠正、暂时放下或已有回应。
- 不替用户决定，不诊断，不把短暂情绪上升为人格结论。
- `currentSituation` 写现实处境；`innerTension` 写感受、需要、担心或价值拉扯；`latestChange` 只写本次新增部分；`whyNow` 说明此刻为什么值得关注。
- 默认 `supportMode` 为 `listen`。只有用户明确希望梳理、比较、行动、深入思考或只记录时，才使用其他帮助方式。
- 只有输入提供消息 ID 时才填写 `sourceMessageId`；否则使用空字符串，不得捏造。

结果只是变更提案。没有对应 Host 操作的成功结果时，不得声称议题或事件已经保存。

只输出 JSON，不使用 Markdown 代码围栏：

```json
{
  "changes": [
    {
      "action": "create",
      "topicId": "",
      "title": "在关系里总担心表现不好",
      "currentSituation": "正在尝试更自然地靠近喜欢的人，但会反复检查自己的表达。",
      "innerTension": "既希望靠近，也担心显得刻意或被拒绝。",
      "latestChange": "第一次注意到，自己更在意能不能做真实的自己。",
      "whyNow": "这已经影响现实互动中的放松程度。",
      "status": "active",
      "supportMode": "listen",
      "eventType": "clarified",
      "eventSummary": "从担心被拒绝，转向更在意自己是否自然。",
      "eventDetail": "开始区分对方的反应和自己对表现的持续监控。",
      "sourceMessageId": "输入提供的用户消息 ID，或空字符串",
      "evidenceQuote": "我更在意自己是不是显得很刻意"
    }
  ]
}
```

更新时 `action` 为 `update`，并原样填写已有 `topicId`。没有实质变化时输出 `{"changes":[]}`。
